# Проверка качества Dental Legal AI

## Что уже автоматизировано

`services/legal_core/fixtures/evaluation/scenarios.v1.json` содержит 40 синтетических
сценариев. В `baseFacts` общие факты; `factsDelta` заменяет отдельные поля; `defaults`
задаёт ожидаемые значения по умолчанию. Порог суммы из `policy` используется только
для тестов и не является настройкой рабочего сервера.

Запуск из корня проекта с установленными зависимостями:

```bash
python -m pytest -q services/legal_core/tests/test_evaluation_seed.py
python -m pytest -q services/legal_core/tests/test_analysis_diagnostics.py tests/test_gateway_packaging.py
```

Проверяются правила сбора фактов, план запросов, приоритет дат, граница суммы риска,
ранняя эскалация, неизвестные сигналы, отказ без проверенных оснований и ограничения
черновика. Текст с SYNTHETIC_CANARY не должен попадать во внешние embedding-запросы.
Проверка не вызывает модели, не загружает нормы и не меняет production-базу.

**Это не эталон правильных юридических ответов.** expectedDomainRisk фиксирует
результат отдельной текущей функции. Он не доказывает полноту политики риска и
не разрешает публикацию при непройденных остальных проверках. Сценарии privacy и
documents-unknown специально показывают вопросы для следующей проверки политики:
текущий LOW нельзя трактовать как доказательство безопасности ситуации.

## Как превратить набор в юридически проверенный

Для каждого выбранного сценария специалист заполняет отдельную карточку по шаблону
`lawyer-review-template.md`. Нужны конкретные фрагменты и применимые редакции, а не
ссылки только на название закона. Юридические ожидания хранятся отдельно от снимка
технических правил; изменение risk policy оформляется новой утверждённой версией.

Последовательно измерять: наличие нужного фрагмента в выдаче поиска, поддержку
каждого вывода источником, учёт неизвестных фактов, полноту ответа, ошибочные допуски
Verifier, долю отказов, задержку и стоимость. Пока карточки не проверены, процент
прошедших технических тестов не является процентом юридически верных ответов.

На следующем этапе требуется отдельный runner для approved-корпуса и настроенных
Hermes, а также фиксация версии промптов/моделей/источников. В этом изменении живой
LLM-бенчмарк, автоматический цикл исправления выводов и UI правок юриста не добавлены.

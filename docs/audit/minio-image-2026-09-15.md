из Docker Hub с `pull access denied`. Compose и интеграционные тесты теперь используют

## Известная уязвимость и следующий шаг

Апрельский выпуск затронут **CVE-2025-62506 / GHSA-jjjj-jwhf-8rgr**, High, CVSS 8.1.
Учётная запись service account или STS с ограниченной session policy может создать
дочернюю учётную запись с более широкими правами родителя. Исправление находится в
`RELEASE.2025-10-15T17-29-55Z`; производитель не указывает workaround.
Источник: [официальный advisory MinIO](https://github.com/minio/minio/security/advisories/GHSA-jjjj-jwhf-8rgr).

В текущем Compose MinIO не публикует host-порт и доступен только через внутреннюю сеть;
клиент использует root credentials, а не ограниченные STS/session-policy credentials.
Это ограничивает применимость описанного сценария к текущей конфигурации, но не
исправляет уязвимость и не является основанием считать старый выпуск безопасным.
Перед использованием ограниченных service accounts и перед запуском с реальными
документами требуется обновление хранилища.

Безопасный путь: резервная копия и проверка восстановления; отдельная сборка
официального исправленного выпуска из закреплённого commit; проверка S3 API,
миграции существующего volume и политик доступа на копии стенда; затем отдельное
обновление production с планом восстановления. Последний security release требует
сборки контейнера из исходников: [официальные release notes](https://github.com/minio/minio/releases/tag/RELEASE.2025-10-15T17-29-55Z).
В этой правке сборка и обновление версии не выполнялись.

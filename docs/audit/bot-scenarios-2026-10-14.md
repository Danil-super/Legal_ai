# Аудит сценариев бота — 14 октября 2026

## Область и статус

Продолжение согласованного унифицированного ввода V2 и плана действий
из SPEC-report-action-plan.md. Проверяется существующий клинический бот;
личное направление, новые роли, категории данных, модели и risk policy не
включаются. Исходный аудит подготовлен в PR #94 до выпуска; после отдельного
разрешения владельца исправления выпущены. Итоговые проверки ниже не подтверждают
готовность юридических ответов: оба новых live примера завершились BLOCKED.
Перечень возможных описаний пользователя бесконечен: это аудит перечисленных
переходов и границ отказа, а не доказательство отсутствия любых будущих ошибок.

Основное дерево реализации: feature/action-plan-report-20261013. Независимые
воспроизведения и ревью выполнены в отдельных ветках. Code Graph MCP использован
перед изменениями и обновлён; его сервер индексирует прежнее корневое дерево
и не охватывает все Python-зависимости. Дополнительно обновлён индекс точного
worktree через CLI. Отсутствие dependents не принято за доказательство безопасности.

## Воспроизведённые дефекты и решения

| Дефект | Исправление и регрессия |
| --- | --- |
| Быстрый ввод создавал V1, пошаговый — V2 | Оба новых пути создают подтверждаемый V2; прежние V1 не переписываются |
| Файл кейса перехватывала библиотека клиники | Production PTB dispatcher пропускает MATERIALS к выбранной анкете |
| Фото/неподдерживаемое медиа оставалось без ответа | Явное сообщение о TXT/PDF/DOCX и ограничении размера |
| Старая кнопка изменяла другой черновик или отменяла новое значение | V1/V2 контролы привязаны к последнему реально отправленному prompt |
| Отозванному пользователю показывалась cached фабула | Защищённый Core GET до вывода и применения ввода |
| Потерянный ответ upload/PUT оставлял неверную revision | Восстановление подтверждённого server snapshot, без обещания несуществующего результата |
| Upload receipt давал свежую revision старым cached фактам | Защищённый read до обработки материала и новый snapshot после receipt; merge только attachment flags и optimistic PUT |
| ACK ожидал Core read; при исключении отправлялся повторный ACK | Раннее подтверждение callback, ограниченный жизненным циклом update факт ACK |
| Кириллическое имя падало до отправки HTTP | Явный ASCII percent-UTF8 wire; декодирование ровно один раз и прежний лимит 255 символов |
| Два отчёта одновременно выбирали одинаковую версию | Блокировка tenant-scoped Case перед выделением report_version |
| Просроченный эталонный файл/фабула выдавались до фоновой очистки | HTTP 410 до выдачи/изменения/replay; metadata без текста и файла |
| Новая живая версия позволяла replay старой просроченной фабулы | Проверяется версия из исторического receipt, не текущая версия |
| Чистый CI не имел pdftotext | Native PDF tools установлены явно; тесты не пропускаются |
| Полный Core CI завершался exit 124 у конца набора | Внешний процессный бюджет 120→180 с; тесты и прикладные тайм-ауты не сокращены/изменены |

Тесты воспроизводят ошибки до исправлений. Отдельно проведены и восстановлены
мутации: отсутствие endpoint decoder, двойное декодирование `%20` в Unicode
имени и проверка текущей вместо исторической версии receipt. Они дают RED;
исходный production-код после каждой мутации восстановлен.

## Проверенные семейства сценариев

| Сценарий | Тип проверки и ожидаемая граница |
| --- | --- |
| /start, /menu, назад, отмена, переключение/возобновление черновика | Настоящая PTB composition; сеть синтетическая |
| Один текст и пошаговая анкета | Оба создают V2, подтверждают фабулу, сохраняют UNKNOWN и исходное описание |

| Повторное нажатие, старая кнопка, потерянный HTTP-ответ | Идемпотентность и восстановление без перезаписи более свежих фактов |
| Вложения, русский/emoji/%-filename, повреждённые/небезопасные файлы | Wire/unit + реальные PG endpoints; прежние MIME/privacy/size/tenant gates |
| Устаревшая подписка/отозванный пользователь/другая клиника/групповой чат | Access-negative tests; серверный tenant context и RLS |
| LOW/MEDIUM и HIGH/CRITICAL, сумма около 10 000 ₽, срочные факты | Существующие v4 tests; очередь/уведомления/взятие дела юристом; policy не меняется |
| Нет утверждённого/применимого evidence, неверный источник или модельный ответ | Реальные Core/orchestrator/worker integration с синтетическими ответами модели |
| Утверждение нормы → retrieval → verified conclusion → отчёт/PDF | Реальные HTTP-сервисы и PG; model boundary синтетическая |
| Группы норм, справочные файлы, утверждения/скачивание | Существующие editor/library/API tests; никакого auto-approval |
| Эталонные кейсы и срок хранения | API/retention/runner tests; DRAFT не выдаётся за утверждённый эталон или правовое основание |
| Отчёт и план действий | Шесть разделов только из CanonicalReport; точные основания и ограничения, без автосообщения пациенту |

## Незакрытые границы релиза

- Локальный объединённый прогон, повторное ревью и CI завершены; выпуск отдельно
  согласован владельцем. Post-deploy smoke выявил незакрытый юридический gate:
  оба примера без подтверждённого юридического ответа (см. итог выпуска ниже).
- 67 частных эталонных кейсов не получили подтверждённой оценки юридического
  качества; DRAFT-пакеты не отправлялись модели и не утверждались автоматически.
- Для пакета эталона есть отдельное предложение усилить авторство/reviewer
  independence. Текущий контракт запрещает автору версии её утверждать;
  изменение прав uploader/submitter требует выбора владельца. Точная
  несогласованная proposal/reproduction сохранена в
  docs/reviews/2026-10-14-reference-package-authorship-proposal.md, не скрыта
  пропуском существующего теста.
- PTB harness без запущенного JobQueue не доказывает фактический тайм-аут
  production ConversationHandler; его warnings не подавлялись.
- Тесты и model smoke не заменяют юридическую проверку применимости норм и
  качества ответов. Hermes memory не является правовым основанием.

## Дополнительная диагностика воздержания — 14.10.2026

Новая изолированная ветка основана на production main f4eaee8. Изменения
приложения, production-конфигурации, прав, policy и утверждений не выполнялись.

- Реальный context прежнего вымышленного manual-кейса передаёт
  `INTAKE_VERSION` строкой `GUIDED_V2`, не вложенным объектом. Гипотеза об
  ошибочном определении V2 в research prompt опровергнута.
- Повторный process-local research на прежней проекции и тех же 14 фрагментах
  завершился за 33,84 с: claims=0, internalRecommendations=5, draft присутствует.
  Упомянуты неизвестные платный характер услуги и дата её оказания, отличие
  EVENT_DATE от даты услуги, отсутствие оснований устанавливать дефект,
  возврат или срок. Эти рекомендации не верифицированы и не опубликованы.
- Контролируемое сравнение изменило только in-memory EVENT_SUMMARY: добавлены
  вымышленные платный характер услуги, дата услуги 14.10.2026 и просьба принять
  сообщение/объяснить рассмотрение, а не определить врачебную тактику.
  Источники и модели прежние. Обычный `reason()` прошёл за 59,78 с: два claims,
  два reviews SUPPORTED, draft присутствует. Dependencies: EVENT_SUMMARY,
  EVENT_DATE и AFFECTED_SERVICES. Это bundled contrast, не однофакторное
  доказательство причины: одновременно уточнены несколько обстоятельств.
- Core submission, изменение сохранённых фактов/отчётов, новый кейс и Telegram
  отправка в этих диагностических запросах не выполнялись. Model SUPPORTED
  не назван результатом Legal Core PASSED или успешным сквозным READY.
- Независимый изолированный RED proposal воспроизводит отсутствие quality/
  warranty-кандидатов для V2 TREATMENT с INVITED_FOR_EXAMINATION. Commits
  cd91691 и 7195cc1; один RED, baseline не менялся. ADR0056 содержит узкую
  allowlist без этой темы: расширение требует reviewed addendum и не является
  доказанной регрессией или установленной причиной пустых claims.
- Текущие retrieval/projection/reasoning tests: 40 passed за 0,56 с. Это
  локальная техническая проверка, не повторный полный PG/MinIO audit и не
  юридическая оценка 67 эталонов. Новый adversarial review диагностики был
  запрошен, но завершённый runtime-результат не получен; sign-off не заявляется.

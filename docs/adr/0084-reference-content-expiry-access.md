# ADR 0084: срок хранения закрывает доступ к эталонному содержимому

## Контекст и дата

2026-10-14. ADR 0050 и SPEC-reference-evaluation-cases.md ограничивают срок
хранения незавершённых эталонных пакетов 30 днями. API проверял только
фактическую очистку содержимого. Просроченный файл оставался доступен до
следующего успешного storage-first удаления; cached create/revision replies
могли также возвращать сохранённую фабулу.

## Решение и границы

При наступлении `content_expires_at` API прекращает выдачу файла и фабулы,
а также запрещает изменения и replay ответов этой версии: HTTP 410,
`REFERENCE_EVALUATION_CONTENT_EXPIRED`. Метаданные дела остаются доступны,
но `scenarioText` отсутствует и `hasMaterial` имеет значение false.
Проверка replay использует именно историческую версию из сохранённого ответа,
чтобы новая текущая версия не открывала просроченную старую фабулу.

Сроки 30/90 дней, отсутствие срока у approved версии, grant/tenant checks,
перечень авторов, запрет self-review и порядок физического удаления прежние.
Объект удаляет существующая очередь; API не удаляет его при чтении и не
переписывает idempotency receipts. Новых категорий данных, таблиц или миграций нет.
Ожидание фонового удаления отвергнуто: его ошибки не продлевают доступ.

## Проверка и выпуск

Тест в отдельном PostgreSQL с вымышленным файлом воспроизвёл HTTP 200 после
истечения срока. Проверяются download, metadata, create replay и submission.
Существующие upload/review/revision и storage-first retention тесты проверяют
сохранение действующих сценариев. Выпуск требует проверки объединённого diff.

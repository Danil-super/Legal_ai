# ADR 0080: единая правовая база с подтверждением только новых норм

## Контекст и дата

2026-10-12. Владелец попросил убрать повторное подтверждение утверждённых групп,
дублирующий текст и отдельные входы «Нормативная база» / «Проверка норм».
Read-only проверка production обнаружила 54 утверждённые нормативные версии,
8 проверенных справочников и завершённость всех семи групп. Кнопка утверждения
показывалась безусловно во всех нормативных группах, независимо от этих статусов.

## Решение

- В главном меню один вход «Нормативная база». Прежние editor callbacks и
  `/review_queue` сохраняются для старых сообщений и ведут в тот же каталог.
- Legal Core, а не флаг Telegram или callback, разрешает editor workspace.
  При точном ответе 403 `LEGAL_EDITOR_NOT_ALLOWED` показывается read-only каталог
  для прежних ролей CLINIC_OWNER / CLINIC_LAWYER с активным доступом. Ошибки сервера
  не маскируются этим переходом. Никакие дополнительные роли не выдаются.
- `/v1/legal/library/groups[/{group}]` — добавочный metadata-only GET-контракт:
  asOfDate, page 1–100, selectedGroup, hasMore, семь названий groups, максимум
  десять items. Корень не запускает тяжёлый поиск фрагментов. Внутри группы
  выбираются десять документов и один lookahead в стабильном порядке.
- Статус source/approval/hash и дата остаются в прежнем
  `production_legal_fragments`. Подготовленная связь определяет только раздел,
  не право использовать документ. Старые утверждённые версии не скрываются
  из-за появления pending-версии. Оригиналы и approval ledger не меняются.
- Имена групп/документов находятся только на кнопках. Внутри editor group
  подтверждение норм скрывается при равенстве approvedNormativeVersions и
  normativeVersions по всей группе, не только текущей странице. Справочники
  подтверждаются отдельно и не становятся правовым основанием. Новая pending
  версия возвращает действие подтверждения. Нет автоматического approval.
- Клиническая «База документов клиники» остаётся отдельной: это tenant-owned
  файлы клиники, не глобальные источники права. Личное пациентское направление
  не меняется. Freeze baseline ui.py обновляется только для описанного
  клинического изменения, остальные hash/изоляционные проверки сохраняются.

## Проверка и ограничения

Регрессии проверяют полностью утверждённые группы, pending вне видимой страницы,
проверенные справочники, единственный вход, разрешение/отказ Core, ошибку upstream,
отсутствие дублирующих заголовков и read-only навигацию. PostgreSQL-проверки
сохраняют прежние границы ролей/подписки и исключают pending, будущие и истёкшие
версии. Старый `/library` и его metadata-контракт не удаляются.

Утверждение предоставляет документы retrieval, но само по себе не доказывает
юридическое качество ответа или успех всех вызовов Hermes. Известный ложный
отказ privacy guard на публичном нормативном тексте этим UI-выпуском не меняется.
Нужен отдельный прогон анализа; считать исправление меню доказательством
полной готовности кейсов нельзя.

Откат — предыдущая версия приложения без удаления документов, ролей и событий
утверждения. Миграции и новые зависимости не нужны. Выпуск — после проверок,
независимого ревью и подтверждения владельцем.

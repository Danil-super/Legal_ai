# ADR 0110: Urgent routing also prepares an AI plan

2 November 2026. Implements the owner's approved AI-first resolution contract.

## Incident and decision

Production case 32 was confirmed by a clinic lawyer on 1 November. It had an
early HIGH escalation, no analysis job and no saved AI work product. The enabled
Gateway returned immediately after displaying the early escalation. Thus the
lawyer received a fact card rather than the intended AI proposal to review.

When the existing lawyer-draft flag is enabled, final factual consent now also
queues the existing v2 analysis job after showing the urgent-routing notice.
Core's separate immediate escalation and lawyer alerts remain independent of AI.
The disabled-flag behavior is preserved. No risk/model/source policy changes.

Core exposes `canRequestAiPlan` on an authorized escalation detail. It is true
only for the actual case creator, with the feature enabled, an unresolved
escalation, an eligible case state, and no saved AI or human work-product version.
The workspace uses this hint to offer preparation of previously stranded cases.
Every request is still independently authorized by the existing job endpoint.

An explicit retry can resume the creator's terminal v2 job with a valid retained
HUMAN_REVIEW receipt and no work product. It keeps the job identity, source binding
and original delivery message; clears its lease/error/delivery acknowledgement;
and resets the existing three-attempt automatic budget with an audited previous
attempt count. Queue/running duplicates reuse the same intent. Resolved cases
and any saved work product are never regenerated by this recovery path.

Pending optional generation is presented as pending with no result in the job
wire; the original routing receipt remains in its immutable storage. No final
report is invented. ACK locks and reloads the job so an old delivery waiting on
a lock cannot acknowledge a newly queued attempt. The immutable HUMAN_REVIEW
notice keeps the same destination and case link across retries; the actual AI
plan is always read independently through the authorized work-product endpoint.

## Limits and verification

An AI plan still requires applicable approved evidence, sufficient facts and a
working provider. A successful routing receipt does not prove a plan exists.
Reference scenarios remain a separate reviewed retrieval source, not model
fine-tuning and not normative evidence. Production's 67 DRAFT references are not
silently approved or included by this change.

Regression tests reproduce the missing dispatch, actual workspace controls,
creator/noncreator capability, terminal retry after the third attempt, immutable
saved plans, duplicate intents, resolved-case denial and a real PostgreSQL ACK
lock wait. Existing Core/Agent plan generation, review, source/date/lease and
tenant-isolation tests remain required. No new table or migration is needed.

Existing delivery behavior for duplicate submissions is retained: completion
updates the original persisted message; a later temporary status card can be
refreshed manually. The plan is available from the case workspace.

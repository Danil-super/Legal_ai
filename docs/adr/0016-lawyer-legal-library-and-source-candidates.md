# ADR-0016: Нормативная база юриста и контролируемое поступление источников

- **Статус:** Принято
- **Дата:** 2026-09-04

## Контекст

Юрист клиники должен понимать, на какие документы Legal Core вправе опираться при подготовке
отчёта. При этом администратору нужен короткий рабочий интерфейс, а внутренние документы
клиники не являются источником права.

Не всякий файл, присланный даже квалифицированным юристом, можно немедленно использовать в
юридической рекомендации: требуется проверить официальный источник, полноту версии, даты
действия, контрольную сумму и применимость к сценарию. Прямая Telegram-загрузка нормативного
акта также смешала бы роль юриста по кейсам с ролью платформенного редактора права.

## Решение

1. В Telegram появляется раздел **«Нормативная база»** только для `CLINIC_LAWYER` и
   `CLINIC_OWNER`. Владелец сохраняет все функции других ролей.
2. Раздел показывает лишь метаданные версий, которые уже допущены в production retrieval на
   выбранную дату: название, орган, номер, период действия, число фрагментов, SHA-256 и ссылку
   на официальный источник. Текст нормативного акта, raw-файл, черновики и версии на проверке
   через него не выдаются.
3. Раздел — это список **допустимых** документов, а не утверждение, что каждый документ
   использован в каждом кейсе. Точный набор фрагментов, реально использованных в конкретном
   отчёте, остаётся в `legalBasis` канонического отчёта и его PDF.
4. `CLINIC_LAWYER` не загружает и не одобряет нормативные акты прямо в Telegram. Документы
   клиники остаются отдельным tenant-scoped контекстом и не получают приоритет над правом.
5. Новые нормативные источники поступают через контролируемый platform-side процесс:
   immutable ingestion официального артефакта → проверка `LEGAL_EDITOR` → regression →
   checksum-bound approval. Автоматическое promotion запрещено.

## Последствия

- Юрист видит прозрачную основу работы бота, не получает возможности случайно изменить её в
  момент разбора критического кейса.
- Для будущего back-office можно добавить кнопку **«Предложить источник»** только
  платформенному `LEGAL_EDITOR`: она создаёт `REVIEW_REQUIRED`-кандидат по ссылке на
  официальный источник, но не загружает его в production и не заменяет обязательный review.
- Такая функция потребует отдельного authz-контракта, миграции/audit, проверки allowlist и
  тестов. До её появления controlled ingestion через код/операционный процесс безопаснее и
  быстрее для первого пилота.

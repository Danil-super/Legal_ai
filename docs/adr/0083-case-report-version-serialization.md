# ADR 0083: последовательные версии отчётов одного дела

## Контекст и дата

2026-10-14. Два одновременных POST `/v1/cases/{id}/reports` с разными
Idempotency-Key читали одинаковый максимальный report_version. Один запрос
сохранял отчёт, второй получал необработанный UniqueViolation и HTTP 500.

## Решение и границы

Создание отчёта блокирует tenant-scoped строку Case до чтения текущей версии,
проверки replay и commit. Следующий запрос видит сохранённую предыдущую версию.
Используется существующий `FOR UPDATE` helper; новых таблиц или миграций нет.
Факты, ранее сохранённые отчёты, PDF и idempotency receipts не переписываются.

Повтор с тем же ключом по-прежнему возвращает сохранённый результат; запросы
с разными ключами создают последовательные версии. Изменений tenant/auth,
risk/evidence policy и внешних интеграций нет. Блокировка только idempotency key
не подходит, поскольку разные допустимые ключи изменяют одну последовательность.

## Проверка и выпуск

Синтетический тест в отдельном PostgreSQL воспроизводит два одновременно
прочитанных номера версии: до исправления 201 + IntegrityError; после — два
201. Окно ожидания теста допускает последовательное выполнение под блокировкой.
Выпуск и независимая проверка объединённого diff остаются задачами основного агента.

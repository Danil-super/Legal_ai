# ADR 0072: атомарная подготовка всех частей нормативного пакета

## Статус и дата

Реализация ранее согласованных P8–P11; 2026-10-07. Выпуск — только после review и CI.
Не является юридическим утверждением либо разрешением подставлять реквизиты.

## Контекст

На сервере имеются 50 новых нормативных оригиналов, включая четыре части ГК и две
части НК, но их 54 части ещё не связаны с нормативными версиями. Кнопка группового
утверждения правильно исключает эти подготовки. Одиночный CLI из ADR 0058 не умеет
обработать сборник: запуск части кодекса не должен скрывать остальные части.

## Решение

Добавить операторский `legal_core.prepared_batch_operator`, использующий те же
guarded corpus ingestion и exact-original bindings в одной транзакции. Вход — JSON
`{"schema_version": 1, "part_requests": ["operator-1.json", "operator-2.json"]}`.
Имена ссылаются только на обычные sibling-файлы без traversal/symlinks. Каждый
part request имеет прежнюю схему ADR 0058 и целую immutable preparation, но corpus
manifest содержит только текст выбранной части и её SHA-256. Предыдущий одиночный
CLI по-прежнему отвергает сборники; новый batch валидирует их явно.

Один batch обязан перечислять **все части каждого включённого оригинала**, ровно
одну текущую подготовку на оригинал и одного действующего LEGAL_EDITOR как
операторскую provenance. Это не доказательство личного решения этого юриста.
Состав выбранных оригиналов задаёт оператор; batch не объявляет весь production
пакет комплектным без отдельной сверки. До commit исходные receipts блокируются
в порядке UUID, чтобы конкурентный импорт не обошёл проверку latest revision.

Нужны подтверждённые поля идентичности, даты, evidence locators, полнота извлечения,
точные диапазоны всех частей, исходный заголовочный URL и исходные байты. Batch
ничего не скачивает, не придумывает и не исправляет. Неполная preparation остаётся
blocker, а не автоматически становится FULL_DOCUMENT. Профиль источника остаётся
ровно прежним Garant revision 1. Существующие corpus/source/approval guards сохранены.

Не более 200 requests; суммарно не более 80 MB исходников и 80 MB UTF-8 текстов
по уникальным включённым оригиналам, плюс прежние индивидуальные ограничения.
Дубли частей, расхождения редакций/актора, отсутствующая часть и ошибка позднего
binding прекращают операцию целиком. По умолчанию — dry-run с rollback. Только
`--commit` сохраняет REVIEW_REQUIRED; точный повтор возвращает прежние bindings.
Ошибки и CLI выводят только безопасные статусы/счётчики, без текста документов.

## Последствия и проверка

Ни новых таблиц, прав, внешних сервисов, LLM, autoapproval, ни изменения policy.
Подтверждение норм по-прежнему выполняется юристом через отдельный authenticated
group preview/attestation. Подтверждение справочников не становится нормой.

Synthetic tests: целый сборник, отдельные scoped texts, пропущенная часть,
дубли/paths/symlinks, разные акторы/preparation digests, приватные ошибки, PG dry-run,
полный commit/replay, поздняя ошибка второго binding с rollback первого, появление
в group preview при отсутствии approval events. Полный pytest/Ruff/mypy/Compose и
независимый review обязательны. Реальный пакет этим commit не импортируется:
недостающие реквизиты/полнота требуют отдельной подготовки и проверки.

Откат к прежнему коду не удаляет originals, preparation history, версии или решения
юриста. Batch не запускается автоматически ни при деплое, ни по Telegram callback.

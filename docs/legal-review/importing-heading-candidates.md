# Подготовка карточек из переданного юристом пакета

`legal_core.preparation_candidates` создаёт настоящий пакет для существующего
атомарного импортёра, а не только отчёт о найденных реквизитах. Вход — приватный
экспорт последних preparation-карточек с текстом и неизменённая директория
оригиналов. Каждое имя файла и SHA-256 должны совпадать с receipt. Все оригиналы
обязательны; менять part keys или подменять старые исходники нельзя.

```bash
python -m legal_core.preparation_candidates \
  /private/baseline/package.json /private/originals /private/enriched
python -m legal_core.preparation_import /private/enriched/package.json --validate-only
```

Генератор по умолчанию требует 58 оригиналов. Выходная директория должна быть
новой; она имеет права `0700`, файлы — `0600`. Подготовленный пакет не помещается
в git. После проверки конкретного пакета оператор запускает существующий
`preparation_import` в согласованном окружении: он атомарно добавляет неизменяемые
revision-карточки и повторяем при retry. Оригинальные receipt не изменяются.
LEGAL_EDITOR продолжает выполнять юридическое подтверждение через рабочее место.

Фактическая read-only сверка 2026-10-07 с пакетом `garant-2026-09-25`:

| Проверка | Результат |
|---|---:|
| Оригиналы с совпавшими локальными и серверными SHA-256 | 58/58 |
| Нормативные RTF / предполагаемые части | 50 / 54 |
| Ссылка именно из совпавшего титульного абзаца RTF | 50/50 |
| Тип акта / дата принятия или подписи — кандидаты | 54/54 / 54/54 |
| Полный номер акта, включая буквенные суффиксы | 53/54 |
| Издатель, явно названный в титуле | 32/54 |
| Сохранённые справочные карточки | 8/8 |
| Ключи одноактных / сборных частей | 48 `document`; ГК 4 и НК 2 `part-N` |
| Извлечение после обогащения | Все 58 `PARTIAL` |

Справочные карточки и их текст сохраняются без изменения; их подтверждение не
становится нормативным approval. У нормативных карточек заполненные поля имеют
явные locator с пометкой `Candidate only` и отпечатком преобразованного текста.
Ссылка из заголовка — наблюдение в переданной копии, а не онлайн-сверка редакции.

Минимальная оставшаяся работа по нормативным версиям конкретна: установить
каноническую идентичность, публикацию, точную редакцию и её действие для каждой из
54 частей; дополнить 22 отсутствующих издателя и реквизиты одного безномерного
обзора; подтвердить полноту преобразования относительно исходного файла и
сформировать подходящие фрагменты. Затем существующий corpus loader создаёт
REVIEW_REQUIRED версии, а точные bindings соединяют их с объявленными частями.
Эти сведения нельзя получить подстановкой даты принятия в дату действия или
автоматическим присвоением издателя по типу акта.

В сформированном пакете отсутствуют 54 canonical_key, 54 publication_date,
54 version_date и 54 effective_from. Поэтому импорт обогащённых карточек помогает
юристу проверить реквизиты, но ещё не делает все нормативные группы доступными
для массового утверждения. Ни генерация, ни validate-only, ни технический import
не создают APPROVED нормативных версий.

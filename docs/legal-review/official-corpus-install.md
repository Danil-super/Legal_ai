# Установка официальных нормативных документов

В репозитории подготовлены неизменяемые PDF и manifests ПП РФ №736 от 11.05.2023
и ПП РФ №659 от 30.05.2026. Для обращений с 01.09.2026 подготовлена содержательная
выборка ПП №659. Наличие PDF в репозитории не означает, что документ уже импортирован
в базу или одобрен юристом.

## 1. Проверить файлы

Из корня проекта, в установленном окружении Python:

```bash
python -m legal_core.official_fetch --manifest services/legal_core/corpus/official/pp736-a7de08b6176991ed.json --verify-only
python -m legal_core.official_fetch --manifest services/legal_core/corpus/official/pp659-7af320a12723f96f.json --verify-only
```

Если PDF отсутствует в локальной копии, повторите соответствующую команду без
`--verify-only`. Загрузчик обращается только к `publication.pravo.gov.ru` и принимает
только PDF с исходным SHA-256 и размером из manifest. Уже существующий файл с другими
байтами не заменяется. Сами manifests, даты юридической применимости и состояние
проверки не изменяются. Команда ничего не записывает в БД и не выдаёт юридическое
одобрение. Для настроенного изолированного прокси поддерживается существующая переменная
`LEGAL_WATCH_PROXY_URL`; произвольные прокси не принимаются.

Официальные PDF:

- [ПП №736](https://publication.pravo.gov.ru/file/pdf?eoNumber=0001202305120025).
- [ПП №659](https://publication.pravo.gov.ru/file/pdf?eoNumber=0001202606010083).

Если сеть не открывает официальный портал, используйте исходные PDF из полного
checkout репозитория либо перенесите точно эти PDF, скачанные с официального портала,
рядом с manifests. Затем выполните `--verify-only`. HTML-страница ошибки, поисковая
выдача или пересказ закона не заменяют PDF.

## 2. Импортировать после миграций

В окружении с доступом к БД и настроенными переменными PostgreSQL:

```bash
python -m legal_core.corpus_loader services/legal_core/corpus/official/pp736-a7de08b6176991ed.json
python -m legal_core.corpus_loader services/legal_core/corpus/official/pp659-substantive-selection.json
```

Обе команды создают `REVIEW_REQUIRED`. Повторный импорт тех же неизменённых данных
возвращает существующую версию. В развёрнутом Compose эти команды можно выполнить
через `docker compose exec legal-core python -m ...`, используя те же пути от `/app`.

## 3. Проверка юристом

Платформенный `LEGAL_EDITOR` проверяет PDF, действующую редакцию, период применимости,
качество OCR и каждый фрагмент по [пакету проверки](initial-corpus-review.md).
После отдельного ручного решения одобренные фрагменты могут использоваться для
соответствующих дат. В извлечённом OCR встречаются артефакты распознавания; загрузчик
подтверждает целостность, но не заменяет эту проверку. Двух постановлений недостаточно
для всех вопросов по ответственности, персональным данным и правам пациента.

## Результат сетевой проверки 15.09.2026

- Попытка получить ПП №659 через новый CLI завершилась ошибкой доступа к официальному
  порталу; прямой запрос PDF также получил HTTP 502. Новый PDF не был сохранён.
- Официальные страницы консолидированных актов на `pravo.gov.ru` для 323-ФЗ,
  152-ФЗ и Закона №2300-1 не открылись при проверке. Полные тексты актуальных
  редакций не импортированы и не помечены как проверенные.
- [Страница 323-ФЗ на сайте Минздрава](https://minzdrav.gov.ru/documents/7025-federalnyy-zakon-323-fz-ot-21-noyabrya-2011-g)
  доступна для просмотра, но содержит публикацию 2011 года. Актуальность её редакции
  на дату обращения не подтверждена; она не добавлена в рабочий корпус как действующая.

Эти ограничения относятся к проверочной среде. На сервере с доступом к порталу
нужно повторить загрузку. Автоматического обхода проверки юристом нет.

## 4. Пакет, переданный юристом

Для исходных файлов, у которых ещё не подтверждены все реквизиты версии, используйте отдельный
входящий контур. Храните пакет в защищённом каталоге хоста и однократно передайте его в уже
запущенный контейнер Legal Core, например:

```bash
container_id="$(docker compose ps -q legal-core)"
docker cp /srv/dental-legal-ai/legal-review-inbox/garant-2026-09-25 \
  "${container_id}:/tmp/review-materials"
docker compose exec -T --user 0 legal-core python -m legal_core.review_materials \
  /tmp/review-materials \
  --package-key garant-2026-09-25
```

Перед `docker cp` убедитесь, что каталог назначения ещё отсутствует: повторное копирование
в существующий каталог может создать вложенную папку. Для повторного импорта запускайте
только Python-команду. `--user 0` нужен для чтения защищённого пакета, скопированного от root;
основной процесс сервиса продолжает работать от своего непривилегированного пользователя.

Команда принимает безопасные RTF-копии и PDF как клинические справочные материалы. Если ссылка
`internet.garant.ru` отсутствует или неоднозначна, источник остаётся неустановленным — это не
причина терять исходный файл и не основание выбирать произвольную ссылку. Импорт сохраняет
оригинал и контрольную сумму, но не создаёт `LegalVersion`.

Только `LEGAL_EDITOR` может открыть файл в разделе «Проверка норм → Загруженные материалы»
или через `/review_queue` → «Загруженные материалы». Доступны тематические группы со
счётчиками, страницы по десять файлов и возврат к общему списку. Повторный запуск с тем же
ключом и неизменными файлами не создаёт дубликаты и сохраняет первоначальное время получения.

Импорт не является одобрением: до попадания в рекомендации нужна полная версия с реквизитами,
датами действия и проверенными фрагментами, после чего — отдельное решение юриста.
Переход из входящего материала к утверждению есть только при наличии уже подготовленной
версии с совпадающей контрольной суммой оригинала. Подготовка всех новых версий из этого
пакета и интерфейс заполнения недостающих реквизитов пока не завершены. Группировка и
скачивание не означают, что для всех 58 файлов уже доступна кнопка утверждения.
